# Git Changes status and Files ancestry — 2026-09-21

## Problem and owner

Git Changes showed nontracked files as `Added` with a green `+N −0` count, which suggested a staged or tracked diff. In the selected real project, `git status --short` reported `??` for the four files visible in the screenshot; `git ls-files --stage` reported none of them. The project Git snapshot is the authority, not the Files watcher or the displayed counters.

## Change

- Keep untracked (`U`) distinct from tracked/staged added (`A`) in the Git snapshot and Files presentation. Show an untracked file's line count as `N lines`, not a `HEAD` insertion/deletion diff. Its diff still compares an empty base with its current content; staging it changes the status to `A` on reconciliation.
- Derive status letters for changed files and each ancestor directory from the same Git snapshot, including both sides of a rename and the former path of a deletion. Do not invent deleted nodes in the normal Files tree. Markers disappear when a subsequent Git snapshot is clean.
- Give the Changes view a persistent, labeled Back to Files control so returning to the existing tree does not depend on rediscovering the toolbar toggle.
- Reduce the shared Files/Sub-agents slot default/minimum from 540 to 500 px and reclaim horizontal toolbar padding without removing action labels or icons; existing explicitly saved wider widths remain user-controlled.
- Reduce the Files toolbar's trailing inset so no dead strip remains after Refresh while the action stays integrated with its group. Remove the custom red deletion border and override CodeMirror's light collapsed-context gradient with semantic app colors.
- Add a direct historical review link next to a successful, exactly recorded apply_patch tool call. The recorder stores bounded before/after text with exact session/call/change identity. This review does not change when the file or Git working tree changes later; it supports multiple edited files. Failed, approximate and oversized operations receive no review link.
- In Changes and historical Review, keep the Files toolbar visible but disable New file, New folder, Rename, Delete and Reveal. Back returns to the previous Files/Changes view. No Git write operations were added.
- Replace the stacked Changes-list/diff preview with mutually exclusive full-height states. Back from a Git diff returns to Changes; a historical review returns to its originating view. The unified editor centers the first changed chunk on opening.
