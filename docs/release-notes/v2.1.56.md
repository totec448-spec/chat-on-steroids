## 2.1.56 Stuck turns you can end, a steadier model choice, and a big round of fixes
A Stop now ends a turn that no browser page holds, a requested reasoning level opens the chat without a model setting, Goal chats stop stalling on short answers, very long recordings open in a second instead of minutes, and files, Git commits and workers hold up better when something is interrupted.
### 👉 After updating
- Nothing to do. The browser extension updates itself.
### ✨ New
- **Suppress unattributed call notices.** A new switch under Settings → General → For developers leaves out the informational "Identity notice" block for an MCP client that has no ChatGPT conversation identity and can show only one text block of a tool result (a custom MCP app in another assistant, for example). It is off by default and changes nothing for ChatGPT.
- **Development builds are labelled.** A checkout run from source now says "Chat On Steroids (dev)" in the window title, the headers, the tray and About, so it is not mistaken for the installed app. Your data folder does not change.
### 💪 Better
- **Stop ends a turn that no browser page holds.** After a page was lost and recovery gave up, the app could not end the open turn: queued messages waited behind it and Stop answered "not running". Stop now closes that turn in the record, and the queue goes on.
- **Goal does not stall on a short answer.** A short answer that ended while the page was still telling the app that the previous message was sent was never replied to, and the chat sat on "Answer settling". The page now looks at that answer as soon as it is free.
- **The model choice is steadier.** A requested reasoning level now opens the chat without a model setting in the address, which made ChatGPT take the level back when the picker closed. A native Enter that had already set the level you asked for is accepted instead of refused as unreadable.
- **The Goal step reviewer list tells two models with one name apart**, as the other model lists do ("GPT-6 · Pro" and "GPT-6 · gpt-6").
- **Very long recordings open fast.** Opening an 83 MB session took 94 s of processor time; it takes about 0.3 s now, and a line that straddled a read block is no longer dropped. The repair pass no longer rereads the journal of every chat that holds an unproven call each time.
- **Workers start more reliably.** A fresh worker's page has 120 s to pick up its task (it had 45 s), and a page that redeems late gets the normal time for each step it reports. The final recovery reload reads the tab again before it acts, and the show of a stuck chat that no browser took is tried once more.
- **Calls are filed in the right chat.** A running request's calls go under the chat's new session after its session was deleted, a compaction pickup waits for the activity request that is still in flight, and a rotation Stop starts only after the call's answer has gone out.
- **A finished command shows its own duration** in the browser transcript.
- **Files, Git and workers survive interruptions.** Two Files renames can no longer overwrite each other, a failed preview after a save no longer reports a failed save and no longer narrows the file's permissions, a Git commit whose hook finishes late keeps its branch, and a worker archived late is restored correctly.
- **Smaller fixes.** Counts, sizes and durations never round up into the next unit's number; an indented line after a heading is read as code; Windows device names such as `conin$` and `com0` are refused in a plugin bundle; a long Project-entry failure reason is kept in the log.
- **Clearer diagnostics.** When a saved state file the app must not replace cannot be read, the log now says whether the file is damaged or the system refused the read.
