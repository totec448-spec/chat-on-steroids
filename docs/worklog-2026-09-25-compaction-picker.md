# Compaction pickup and model picker

## Evidence and scope

The installed alternate-shell session again abandoned a manual continuation before source
dispatch, about five seconds after a compaction reload. The installed extension matched the
previous package. The pre-dispatch state, absent handoff and absent destination are proven;
the precise native DOM condition which refused Send was not logged. The local job projection
requirement in the new in-place repair still allowed a newly persisted ticket to cause reload.
A later controlled run of that same installed baseline successfully completed the handoff and
committed the successor, confirming this is intermittent, not that the new patch is live-proven.

## Changes

- Carry continuation identity separately from browser repair identity. The responsive document
  reserves its existing compaction operation synchronously and revalidates the exact existing
  ticket before interruption or prompt acquisition. Missing local job projection no longer
  causes reload. Cancelled/replaced tokens cannot create or acquire a new transaction.
- Preserve the original token across the source settle barrier and prompt request. Keep the
  existing sourceAttempt/sourceDispatch custody; no duplicate click after ambiguous dispatch.
- A pre-dispatch Send-readiness refusal retains the same ticket for the existing bounded pickup
  owner. Its visible local error prevents immediate activity-driven retries. Changed source,
  occupied draft and other terminal failures retain their conservative handling.
- A responsive refusal cannot authorize reload. Recheck tab/document identity after the probe.
  In-place recovery does not set reload cooldown or replacement-document bookkeeping.
- Separate the composer model list from the selected model's effort slider; expose full labels,
  selection check, keyboard focus and effort captions using existing theme tokens. Expand known
  abbreviated native names only for presentation, preserving exact execution ids and existing
  eligibility/exclusions. No discovery/provider or Internal Chromium hosting changes.

## Validation

Focused new-ticket, cancelled/replaced ticket, busy duplicate, dispatch and model-picker
regressions passed during development. One duplicate-press fixture omitted the token that main
always returns; it now supplies that actual contract rather than bypassing the new token check.
Two recovery mocks returned an untyped object for an unavailable document; unavailable replies
retain legacy reload handling, while explicit responsive refusal does not.

Mainstream full verification passed: privacy, notices, typecheck, 6,084 tests (46 skipped),
then 26 native/shutdown tests. The native pair also passed separately with one worker.
Internal typecheck and four boundary suites passed 1,560 tests. Final focused extension/picker
checks passed 48 tests in each repository after the last test additions and single-effort UI
adjustment. Shared content, DOM, picker and corresponding shared test files match byte-for-byte;
Internal's intentional browserTabs hosting adapter is preserved. Both diffs pass whitespace checks.

Internal x64 NSIS build and packaged native runtime smoke passed (Electron 44.3.0, sharp 0.35.4,
vips 8.18.6, PTY and parser). Installer size: 173,383,923 bytes; SHA-256:
`DDDA903D593ED99DB91ED75E2022259441AB224054872843B595350E254FEB73`.
The remote copy matches. The per-user installation exited successfully; installed app.asar and
the changed extension files match the package/source hashes. The installed picker shows the
full model name and a separate effort control within the viewport.

The post-fix live source request acquired an exact sent receipt. A later readback found the
same local session bound to its successor with no active turn; the user also confirmed that
Compact completed. This run logged reload recovery, so it demonstrates the real end-to-end
flow but does not independently prove the in-place branch (covered by regression tests).

UI smoke uses an isolated temporary Electron harness outside either worktree; it does not
load the production bridge. Mechanical style scan reported existing app-wide findings, not
