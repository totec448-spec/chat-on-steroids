## What came of this round, for the reader jumping in later

- **Check 50 is fixed** — see `src/main/mcp/kernel.ts`'s `toolDisabledMessage`, which now
  defaults an unlabeled capability's refusal to its own Settings row name.
- **Checks 33/45/46 are not fixed by this round.** `extension/browser-driver.js`'s scroll-target
  detection (the fix aimed at check 46) is independently verified correct against a controlled
  fixture — 43/43 in `verify:browser`, headless on one machine and headed on this one, both
  against this exact build — but this run's ad-hoc fixture still shows check 46 failing, and two
  checks with code this round never touched (45, 33) regressed in the same run. That pattern, plus
  the "blank white screenshot" and unreachable refs this run also reports, points at instability
  in that specific run's own generated fixture rather than a code defect proven across the board —
  but it is not proven either way. The fixture itself (`cos_qa/index.html`, built through a
  possibly-backgrounded heredoc write) was not preserved. A future round that hits check 46 again
  should keep the fixture file and quote its exact markup around the failing coordinates, so the
  next fix is built on the real page rather than a guess at what it might contain.
