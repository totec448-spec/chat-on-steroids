# Skills library UI — 2026-09-18

The sidebar now opens a Skills page directly below Plugins. It follows the existing Plugins/Pets layout: search, import menu, equal-height cards, empty/no-match states and a confirmation dialog for removal. The page lists the managed CoS library only; project and external discovery remain in the chat composer.

`skills:import` uses an OS picker for either a complete package folder or one Markdown file. Existing `main/skills.ts` validates, stages and publishes it under `<userData>/skills/<id>/SKILL.md`; the renderer never chooses a destination path. `skills:remove` validates the id and moves the exact managed package to OS Trash through the existing serialized store owner. Prepared messages keep their frozen skill text.

The same import dropdown now accepts a public `https://github.com` repository/folder or `SKILL.md` link. `main/skill-github.ts` resolves the ref to a commit, enumerates a bounded package, downloads SHA-checked blobs and passes the complete staged folder to the managed-library owner. A reserved `.cos-github.json` sidecar records the canonical URL and content revision; local package imports cannot forge it. GitHub cards expose manual **Update from GitHub**. An unchanged content revision does nothing. A changed package is staged, swapped under the serialized owner and the previous directory moved to OS Trash; startup restores the previous package if interrupted between the two renames. Local `SKILL.md` edits block update, while the confirmation warns that other local resource edits will be replaced. This adds no background polling, GitHub credentials, root permission or executable hook. Public GitHub API rate limits and the explicit package bounds can reject large imports.

Opening the Skills page now performs a metadata-only GitHub check for installed GitHub packages. The main process reads one bounded recursive tree per repository/ref and derives the same sorted file-SHA revision as import/update, including resources. Results carry the exact installed origin revision; a removal or replacement during the request cannot publish a stale result. The renderer paints checking/current/available/failed states in the card footer without rebuilding cards or stealing an open menu. “Up to date” is quiet static text with a check icon; “Update available” is a real button that opens the existing confirmation dialog. Page navigation reuses results for 15 minutes (failed checks retry after one minute); explicit Refresh checks immediately. At most three repository checks run concurrently. A check never downloads blobs or installs an update; confirmation remains the only installation path. The same repository's installed Skills share one remote request.

Source validation covered typecheck, production build, focused managed-library/renderer/IPC/Pets tests, all nine renderer language tests, and isolated Chromium layout captures at desktop and compact widths, including current/available badges, the import menu and both GitHub dialogs (`outputs/skills-ui/`, ignored by git). Mocked GitHub tests cover full-package import, unchanged/changed update, resource-only changes, grouped metadata checking without blob downloads, concurrent removal, truncated-tree failure, local-edit protection, origin spoofing and interrupted-swap recovery. The mainstream port is validated separately against its external-browser contract; this worklog does not treat behavior from the Internal Chromium variant as mainstream evidence.

The source UI review reported no new Skills-specific defect. A read-only check of the public `openai/skills/.../hatch-pet` folder found 14 files across four directories, within this importer's bounds; the actual network import was not exercised against the user's library.

## Local Skills provenance repair

Older local packages have no `.cos-github.json`, so they cannot truthfully expose an update state. Their cards now show the concise **Local** status and offer **Link GitHub source** in their menu. Linking asks for the public skill URL, verifies the remote `SKILL.md` blob against the local file and the folder-derived id, then writes only CoS-owned metadata. It records the installed package's real file fingerprint, not the remote fingerprint: missing or changed resources yield **Update available** and require the existing confirmed update path. No automatic migration guesses a source from unrelated URLs embedded in a Skill body.

The new `skills:githubLink` IPC/preload boundary validates the exact id and URL. Tests cover matching complete and incomplete local packages, mismatched `SKILL.md`, concurrent removal, renderer error/retry and IPC payload validation. Mainstream port validation passed typecheck, the production build, 359 focused Skills/composer/layout/IPC/packaging/i18n tests, and isolated Chromium checks for Skills, composer and Workspace. Live linking is not performed against the user's library during automated checks.
