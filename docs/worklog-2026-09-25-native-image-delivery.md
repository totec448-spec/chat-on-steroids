## Failure and repair

- The current ChatGPT shell exposes image-only answers as typed `generated-image` items, without an assistant final-text item. Read their exact provider message/asset membership and completed containing turn; previews, running images and foreign identities cannot finish a turn.
- Carry that terminal provider message on `turn_end`. The canonical completion reader requires both this completed boundary and its matching completed native image, in either arrival order. Existing question, turn, rebind and later-work fences still apply. This retires the real activity grant and releases input without inventing an assistant text row or allowing an image preview alone to finish work.
- Current shell image pixels use blob URLs. Bind capture to the mounted typed item and its completed per-image control, keeping existing epoch, ownership, size and asynchronous capture checks. Classic estuary images remain supported.
- Native upload inputs now use React-generated IDs. Elect exactly one enabled input of the requested kind inside the current composer form. Recognize the shell's named image tile and unique remove control, including localized labels, alongside classic attachment controls. Keep upload confirmation distinct from the actual send receipt.
- Delivery errors no longer inherit the 22px status-icon width or single-line ellipsis. They wrap within the existing pending-message layout.
