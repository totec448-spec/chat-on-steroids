# Global Quick Chat

Quick Chat opens a compact COS conversation from a global shortcut (`Ctrl+Shift+E` on Windows/Linux, `Cmd+Shift+E` on macOS), with a tray fallback if the shortcut is occupied. The panel is a separate window over the existing session and delivery infrastructure, not an independent assistant or provider client.

## First increment

- Reusable, resizable panel with the current COS appearance, language and default observed model.
- The same Workspace composer, Markdown transcript, collapsible tool activity, recent chats and search, model and reasoning controls, image/file attachments, clipboard paste and drafts; only the outer layout is compact.
- The history icon opens a dedicated history drawer using the shared chat-search controller; the title is display-only. It starts with the 30 most recent ordinary chats, marks the current one, offers new chat and searches older chats by title or recorded text. Switching retains each chat's drafts and does not drive the Workspace's browser tab. The compact welcome reads “How can I help?” and the native panel waits for renderer initialization before its first show.
- Durable outbox admission and exact session identity. Hiding the panel does not stop the turn. Expanding opens the same conversation in the workspace.
- The Workspace chat row menu offers Open in Quick Chat, opening the exact local session in the existing compact window or after its first renderer initialization. This navigation preserves drafts and does not request a desktop snapshot.
- The same sandboxed preload and security policy as the Workspace, explicit IPC ownership checks on window actions and independent local UI state. Attachment staging protects drafts in both windows.

## Desktop context and quick actions

- Settings → General configures or disables the global shortcut, with native registration status; the tray remains available. Invoking Quick Chat remembers the foreground window identity and, on Windows, attempts to acquire an accessibility text provider. A slow desktop helper cannot delay the panel indefinitely (1.5-second context deadline); a completed window-only identity survives an unfinished provider lookup. The invocation requests a window snapshot, respecting the existing desktop permissions, and a passive click-through overlay highlights the source with a brief diagonal scan. The effect contains no desktop pixels and is independent of attachment admission.
- The snapshot is automatically staged in the invoking composer draft as a removable group with application/title, thumbnail when available, and expandable captured text. Each invocation replaces only its previous automatic context in that draft. Closing the window or switching drafts before acquisition ends prevents a late attachment; nothing is sent until Send. Manual selections remain separate attachments. Generated file names use a unique suffix to reduce provider-side collisions; the browser upload receipt also recognizes an unambiguous numeric collision suffix on an untouched draft.
- General → Chats includes an automatic window context switch (on by default). Turning it off prevents automatic screenshots, accessibility content capture and the scan effect; source identity is still remembered for explicit actions. The header refresh button captures that original window on demand, replaces its prior window snapshot only after successful staging and preserves other attachments. Reopen Quick Chat from the desired source if its identity/title has changed. The panel opens without a full-window fade or composer resize animation; a pending card reserves space until the snapshot arrives. The scan excludes the panel bounds.
- The desktop-context menu explicitly attaches the source window's direct screenshot and bounded visible accessibility context (application, title, visible document text, selection, named controls and image-relative bounds where available). A missing channel can degrade to the other; unrelated screen-fallback pixels are never attached. Selected text includes its source application and title. Attachments use the same staging, draft ownership checks, preview and send flow as the Workspace. Explain, summarize, rewrite and translate attach the selection and prefill an editable prompt, without sending it.
- If Windows UI Automation cannot expose a selection, an explicit selection action can temporarily return focus to the verified source window and copy it with the application's native shortcut: Ctrl+Shift+C for known terminal hosts including Herdr, otherwise Ctrl+Insert. A fresh clipboard sequence and original owner PID must agree; no unchanged clipboard is accepted, and Ctrl+C is never sent. The fallback requires control and clipboard read/write permissions, preserves bounded memory-backed clipboard formats, and restores them only while the captured copy still owns the clipboard. Unsupported clipboard formats fail before copying. Focus returns to Quick Chat only if the source still has focus. Clipboard-only captures cannot authorize replacement.
- On Windows, a completed answer can replace the original editable selection after confirmation. The preview displays the source window, selected range and editable answer. The helper verifies window/app/process/title, live accessibility provider, exact selected range and text, editability, and foreground immediately before input. Short single-line replacements use one Unicode input batch; longer or multiline replacements use a single paste and require clipboard-write permission. A failed input after clipboard publication may leave replacement text in the clipboard.
- Replacement requires a verified editable Windows UI Automation text range; protected, stale or read-only ranges fail explicitly. Applications without a supported text provider or copy chord can still be used via direct window context or manual paste. Direct window screenshots use the existing desktop adapters on Windows and supported macOS versions; Linux context and macOS text selection/replacement are not implemented. All platforms can still use ordinary file/image attachments and copy answers.

## Verification and remaining platform work

The Windows owned-window tests exercise actual UIA selection capture, refusal when expected text differs, replacement, native-copy fallback and refusal to accept an unchanged clipboard. The Electron Quick Chat smoke fixture exercises the shared transcript, tool calls, attachment/draft switching, quick action prompts, replacement preview, clipboard-only selection, combined window attachments, exact send, pin, theme, narrow layout and expand. Shortcut preference/registration, IPC and canonical answer export have targeted tests. The installed build still needs an end-to-end user test with a real provider and external editing apps; macOS/Linux, multi-display scaling and broad performance benchmarks are not validated by these checks.

The compact surface loads the same index.html and chat.ts as the Workspace through entry.ts. Keep feature behavior there and limit quick-chat.ts and quick-chat.css to window controls, initialization and layout. The two windows select chats independently; admitted inputs and recordings are shared.
