# Bug audit — 2026-08-24

> Follow-up: the `session action=history/status` surface discussed in this audit was superseded
> later on 2026-08-24 by `search/read`, explicit session ids, exact authored-message paging and
> update cursors. Those passages remain as evidence about the removed implementation.

Manual source + regression audit of the combined Chat On Steroids tree after the Goal Mode,
Compact & Resume, multi-agent durability, connection lifecycle, MCP/tool-normalization and UI
work was merged into one workspace. A finding is listed as confirmed only when the runtime path
was traced and either the old behavior was reproduced or a regression was written against the
boundary that failed.

The important rule for this pass was ordering, not merely eventual state. Several bugs below
looked correct after the process had been running for another second, but were wrong at the
crash/reload/navigation boundary where the caller decides whether an operation happened.

---

## Confirmed findings and fixes

### 1. Worker messages could become durable before `agents action=message` reported success

**Where:** `src/main/agents.ts`, `src/main/mcp/tools-core.ts`, `src/main/durable.ts`,
`test/agents.test.ts`

The first durability fix staged a message in the broker and hid it from `offerMessages()` until
`persistCriticalSwarmNow()` completed. That closed recipient visibility, but not disk visibility:
`changed()` also invokes the normal `onSwarmPersist` lane, whose production wiring is
`writeDurableSoon(SWARM_STATE, snapshotSwarm())`. The ordinary snapshot still contained the
staged queue entry. Its 300 ms writer could therefore reach disk while the immediate acceptance
write was still held or about to fail. A crash in that interval restored a message whose sender
had never received success.

**Fix:** broker snapshots now have two structurally separate views. Public/debounced
`snapshotSwarm()` excludes `unpublishedMessages`; only the private snapshot consumed by
`persistCriticalSwarmNow()` includes them. A successful immediate write publishes the staged
entries in memory. Failure rolls them back and emits a new committed-only broker revision, so
the durable writer's generation ordering supersedes the failed immediate generation rather than
allowing it to retry later and resurrect rejected work.

**Crash regression:** `keeps an unpublished message out of a debounced disk write while its
immediate acceptance write is held and failing` uses the real `writeDurableSoon` /
`writeDurableNow` generation machinery. It holds the immediate barrier, forces the debounce to
disk, then injects `EBUSY` into the immediate rename. **Before the fix it failed exactly at the
crash point: the supposedly pre-acceptance durable queue had length 1 instead of 0.** After the
fix the held debounce contains no message, the immediate generation contains the staged message,
the immediate write fails, rollback queues a newer safe generation, and final recovery remains
empty. The existing MCP regression also proves a retry after failed acceptance queues exactly
one copy.

### 2. Worker bootstrap ACK could retire the browser command before the worker binding was durable

**Where:** `src/main/bridge.ts`, `src/main/agents.ts`, `test/bridge.test.ts`

A worker page could redeem its durable bootstrap command, bind its conversation in memory and
ACK the command file before the new swarm binding had crossed its own durable boundary. A crash
after the command receipt but before swarm fsync left neither a command to replay nor a durable
binding to recover.

**Fix:** binding/activation is persisted first. Only after the critical swarm snapshot succeeds
may `/commands/ack` replace the leased worker command with its receipt. If swarm persistence
fails the ACK is retryable and the command remains redeemable.

**Regression:** `keeps the worker command durable until the worker binding itself crosses its
crash barrier` pauses the swarm write after the in-memory bind, verifies the durable command is
still present and has no receipt, then releases the swarm write and proves the receipt is written
only afterwards.

### 3. Reused worker ids could inherit a previous run's workspace

**Where:** `src/main/workspace.ts`, `src/main/agents.ts`, `test/workspace.test.ts`

Worker workspaces use stable short keys such as `agent:worker-1`. `inheritWorkspace()` used to do
nothing when the new prime had not learned a workspace yet, so the old value under the reused
worker key survived into the next run. A relative path in the new run could resolve against the
previous run's project.

**Fix:** inheritance now has replacement semantics. Reusing a worker id clears that worker's old
workspace first; the prime workspace is copied only when one exists.

**Regression:** `clears a reused worker id when a new run has no prime workspace yet` seeds the
old worker key, starts a new run without a prime workspace and proves no inherited relative base
exists.

### 4. Durable worker commands were keyed too weakly across swarm incarnations

**Where:** `src/main/agents.ts`, `src/main/bridge.ts`, `extension/background.js`,
`test/agents.test.ts`, `test/bridge.test.ts`

`worker-1` is reused by every run. A durable command from run A could therefore look like the
bootstrap owed by run B. The lost-ACK recovery path also trusted the friendly worker label more
than the exact redeemed command.

**Fix:** every run has a UUID incarnation id; worker commands carry it, dedupe on it and are
retired when that run stops being current. Recovery requires the exact command id that was
redeemed, and stale journal shapes which cannot prove their run are discarded rather than
migrated into authority.

**Regressions:** full-UUID run identity; stale old-run command refusal; stale-event refusal; and
lost-ACK recovery only with the exact command id.

### 5. Restored worker state had two crash-window inconsistencies

**Where:** `src/main/agents.ts`, `test/agents.test.ts`

A legacy crash could leave a worker with a conversation binding but state `invited`, causing a
duplicate worker chat to be opened on restore. A worker that had once been detached could also be
persisted as `finished` while retaining `revivable=true`, allowing terminal work to reopen.

**Fix:** restore repairs bound+invited to active, and terminal finished workers are never
revivable. Binding and activation are now one persistence transition.

### 6. `latestHandoff()` silently ignored sessions after an arbitrary 5,000-entry maintenance cap

**Where:** `src/main/session/store.ts`, `test/session.test.ts`

The latest-handoff recovery API promised to search every recording but reused a directory scanner
whose 5,000-entry cap exists for bounded maintenance work. Once the session folder grew beyond
that count, the newest handoff could be outside the scan and recovery would return an older one
or none at all.

**Fix:** recovery uses its own uncapped summary scan. Maintenance/pruning keeps the cap where it
belongs.

**Regression:** `finds the newest handoff even when its session is beyond the 5,000-folder
maintenance cap` creates 5,001 catalogue entries and puts the newest handoff last.

### 7. One failed durable state file could skip every later shutdown snapshot

**Where:** `src/main/durable.ts`, `test/durable.test.ts`

`flushDurable()` previously rejected on the first named file that failed. During shutdown that
meant a broken `swarm.json` write could prevent an unrelated continuation, correlation or bridge
snapshot behind it from even being attempted.

**Fix:** a shutdown pass attempts every pending state file, preserves failed generations for the
retry machinery, then surfaces the first real error after the independent writes have run.

**Regression:** injected failure for `swarm.json` while `continuations.json` is queued behind it;
the flush remains visibly failed but the continuation reaches disk.

### 8. Compact & Resume could retarget stale asynchronous work across SPA navigation

**Where:** `extension/content.js`, `test/content-script.test.ts`

The browser can navigate chat A → B, or A → B → A, while the compaction settle/watch work is
awaiting tools or browser state. Conversation id alone is insufficient for A → B → A: the id is
the same again while the document lifecycle is not. Old work could continue against the new
document and submit a handoff into the wrong navigation generation. Cancellation also left a
capture capable of completing after it had nominally been abandoned.

**Fix:** compaction work is fenced by **conversation id + navigation epoch**. Navigation clears
stale capture state, and cancellation retires its capture before crossing any later async wait.

**Regression:** `abandons a compaction instead of retargeting it when the tab navigates while
tools settle`, plus the Fiber/epoch generation regressions described below.

### 9. Goal Mode could act after it had been switched off

**Where:** `extension/content.js`, `test/content-script.test.ts`

The page checked Goal Mode before starting a draft, but an OpenRouter request already in flight
could become ready after the user switched the feature off. `maybeSendGoalReply()` then typed and
sent it anyway.

**Fix:** the send boundary rechecks the current activity-fed Goal setting before touching the
composer. Main-process acknowledgement of an in-progress draft also aborts its OpenRouter request
so a cancelled/spent draft stops consuming the key.

**Regression:** `does not send a ready draft when Goal Mode was switched off while it was being
written` and the goal-unit acknowledgement coverage.

### 10. A successful Goal send plus a lost ACK could send the same user message twice

**Where:** `extension/content.js`, `src/main/goal.ts`, `test/content-script.test.ts`

ChatGPT accepting the message is irreversible, while `/goal/ack` is a fallible local hop. If the
send succeeded and the ACK was lost, the app correctly re-offered its unacknowledged ready draft
after a reload; the browser had no durable evidence that it had already spent that token and
could send the same user message again.

**Fix:** immediately after ChatGPT accepts the send, the content script records the
conversation+draft token in a small bounded `sessionStorage` spent-token journal before attempting
the ACK. A reoffered token retries only its acknowledgement. The receipt therefore survives a
content-script reload in the same tab without becoming permanent cross-session state.

**Regression:** `never sends the same ready draft twice when the acknowledgement is lost` loses
the first ACK, reloads the content script and proves the send count stays one.

### 11. Goal Mode had several additional lifecycle and transport defects

**Where:** `src/main/goal.ts`, `extension/content.js`, `src/main/config.ts`, `src/main/bridge.ts`,
`test/goal.test.ts`, `test/content-script.test.ts`, `test/bridge.test.ts`, `test/config.test.ts`

Confirmed and fixed in this pass:

- worker chats inherited the global Goal switch even though their user turns are already driven
  by the prime; Goal is now suppressed for workers;
- Goal phase/error/turn state survived navigation into the next chat; navigation now resets it;
- the two-minute “composer is occupied” window reset its start timestamp on every retry and could
  therefore wait forever; the timer now belongs to the draft;
- empty-answer and watch-timeout exits went visually silent; they now leave an explicit stage /
  reason rather than looking like a loop that never ran;
- SSE parsing could drop a final record or split UTF-8 tail when the stream closed without a
  trailing newline; EOF now flushes the decoder and final buffered record;
- OpenRouter's model catalogue cache was not scoped to the API key, so replacing a restricted
  key could keep the previous key's catalogue for the cache TTL; it is keyed by a one-way
  credential fingerprint now;
- model ids beginning with OpenRouter's `~` family alias were listed but rejected by Save; they
  are accepted, and the default uses the rolling latest alias rather than a stale dated model;
- an unknown future reasoning value caused the whole config parse to fall back to conservative
  recovery, wiping roots/permissions; only the unknown Goal reasoning field is repaired now.

Goal's bridge routes also have explicit disabled/no-key/no-generation/no-session/auth refusals and
one-draft-per-generation idempotency regressions.

### 12. Connect / Connecting state could disagree with the resources actually running

**Where:** `src/main/connection.ts`, `src/renderer/main.ts`, `src/main/ipc.ts`,
`test/connection.test.ts`

The connection audit confirmed four user-visible lifecycle defects:

- after disconnect, connector cards could retain the previous tunnel's `live` state/public URL;
- a terminal tunnel report (`tunnel-unavailable`, auth failure, etc.) could leave the connector
  card looking like it was still “Connecting”;
- changing the active Core transport method/settings while connected could leave old Core
  running while settings and/or Desktop used the new transport;
- the pre-connect folder gate disagreed with surface availability and rejected a valid
  clipboard-only Desktop setup that never needs a filesystem root.

**Fix:** connector presentation is rebuilt from the currently running endpoint; terminal reports
map to surface error; Core-affecting transport changes perform a serialized reconnect while
Desktop-only OpenAI tunnel changes stay hot-swappable; and the folder gate uses the same Desktop
usefulness predicate as publication. Connect/disconnect/applySettings are serialized, and tunnel
callbacks are fenced by a connection generation so a late report from a stopped tunnel cannot
repaint the replacement connection.

The renderer's Connect/Disconnect label and action use the same “running” states
(`starting-server`, `connecting-tunnel`, `connected`, `offline`) as the lifecycle owner, so a fast
double click cannot turn two queued Connect intents into two tunnel stacks.

### 13. Discovery monotonicity leaked across independently cached connectors

**Where:** `src/main/mcp/server.ts`, `test/mcp.test.ts`

Core and Desktop share a loopback listener but are separate MCP discovery units. One global
exposure snapshot let Desktop discovery freeze Core's mutually exclusive `find` vs exec shape
before Core had ever been queried.

**Fix:** exposed capabilities/features/find choice are monotonic **per surface**, matching the
boundary ChatGPT actually caches.

**Regression:** Desktop is discovered first, command execution is then enabled, and Core's first
discovery must expose exec/write_stdin rather than the stale `find` shape.

### 14. Chunked MCP requests had no body-size bound before parsing

**Where:** `src/main/mcp/server.ts`, `test/mcp.test.ts`

The Content-Length guard did not cover chunked/missing-length POSTs. The adapter could therefore
concatenate an arbitrarily large body before JSON parsing.

**Fix:** those requests are read through an explicit 8 MiB bounded collector; bytes beyond the
limit are drained without retention and receive 413, while malformed bounded JSON receives 400.

### 15. A recycled exec session id briefly retained the previous chat's authority

**Where:** `src/main/mcp/tools-core.ts`, `src/main/codex/ownership.ts`, `test/mcp.test.ts`

Managed process ids are intentionally small/reusable, but chat ownership is stored separately.
An exited process could leave its owner row behind. If the allocator reused the integer, the old
chat could call `write_stdin` during the new `exec_command`'s initial yield before the new owner
was published.

**Fix:** the owner row is cleared at allocation, before the new child enters the manager. No one
owns the new integer until its `exec_command` has established the caller.

**Regression:** allocator reuse is forced deterministically; the old chat is refused while the
new process is already live but its starting call has not yet returned.

### 16. Coordinate desktop actions could act on a frame the caller never saw

**Where:** `src/main/computer/index.ts`, `src/main/mcp/tools-desktop.ts`,
`test/computer.test.ts`, `test/tools-desktop-permissions.test.ts`

`frameId` was only “strongly recommended.” The screenshot frame is global, so another chat can
replace it between observation and a coordinate click. Omitting the id then applied coordinates
to whichever frame happened to be latest.

**Fix:** every coordinate action requires the frame id it came from (`FRAME_REQUIRED`) and stale
ids fail with `STALE_FRAME`. Semantic `click_ref` / `set_value` remain frame-independent because
they resolve the real control at action time. The permissions audit also fixed neutral `wait`
actions being rejected when mouse/keyboard control was off even though waiting touches no input.

### 17. PowerShell quote recovery could cost whole command lines without naming the cause

**Where:** `src/main/exec-hints.ts`, `src/main/mcp/tools-core.ts`, `test/exec-hints.test.ts`

A model-written bash-style `\"` inside a PowerShell double-quoted argument terminates the string;
PowerShell rejects the **whole line**, including valid earlier statements, with a parser error
that does not explain the backslash. The recorded failure occurred repeatedly in worker audits.

**Fix:** before other command normalization, only lines that provably fail PowerShell quoting but
parse coherently under bash-style escaping are eligible. The enclosing argument is converted to
a PowerShell single-quoted form while preserving the backslash that the eventual native Windows
argv needs. Interpolation, backticks, doubled backslashes and ambiguous quoting are deliberately
left untouched. Tests execute the repaired line against PowerShell/Win32 argv rather than merely
comparing strings.

The same audit also made benign `rg` exit 1 visible to the model instead of only suppressing an
error counter, preventing pointless search retries. Unknown/ambiguous shell shapes still fail
closed rather than being normalized by guesswork.

### 18. Core tool execution had several false-success / wrong-environment edges

**Where:** `src/main/mcp/tools-core.ts`, `src/main/exec-hints.ts`, `src/main/env.ts`,
`test/mcp.test.ts`, `test/exec-hints.test.ts`

The combined tool audit confirmed and retained these fixes:

- `exec_command` now starts from the shared sanitized child environment rather than rebuilding
  only PATH, so connector/API secrets are stripped and the bundled ripgrep path/system paths are
  preserved;
- command rewrite ordering is quote repair → ripgrep normalization → deterministic bundled-rg
  binding → shell derivation; binding first disables the normalizer because its leading `rg`
  token no longer exists;
- ripgrep option arity is version-pinned and unknown flags disable rewriting rather than risking
  an argument/pattern/path shift;
- PowerShell filename glob expansion is limited to the first statement/current workdir, while
  brace expansion refuses cases needing a second pathname-expansion stage;
- multi-read telemetry counts only paths actually attempted successfully; exhausting the output
  cap no longer counts untouched targets as successes, and an explicit read where every target
  failed is an error rather than a successful response full of `ERROR` sections;
- identity-sensitive relative/default-workspace operations fail closed in an active swarm when
  the exact calling conversation cannot be proven instead of falling back to another root/chat.

### 19. `session` could falsely tell a model that recorded history did not exist

**Where:** `src/main/mcp/tools-core.ts`, session/correlation tests

When exact request identity was unavailable, `session history` answered as though there were no
recordings. That turns an attribution outage into a false factual answer and makes the model
reconstruct work from the filesystem.

**Fix:** unresolved current-session selection says exactly that and lists candidate recordings;
status and no-match history searches provide the same recovery path.

### 20. Goal/settings UI had several concrete interaction failures

**Where:** `src/renderer/*`, `src/main/ipc.ts`, `extension/content.js`, `extension/overlay.css`,
renderer/IPC/extension tests

Confirmed fixes from the UI side of the same pass:

- OpenRouter Keys and ChatGPT Apps buttons were present in markup but absent/stale in the
  `link:open` allowlist, so clicks silently did nothing; every `data-link` is now tested against
  the allowlist;
- the settings grid used an implicit `auto` track, letting nowrap content push switches off the
  right edge; its column is bounded with `minmax(0,1fr)`;
- the Reasoning select inherited a full-width field rule and became a sheet-wide dropdown; it
  sizes to its content and the adjacent action button no longer shrinks first;
- the model picker loaded only the first 20 unless the off-screen button was used, and rebuilding
  the list on page load reset scroll position; near-end scrolling now pages in place;
- popup surfaces named a `clf-pop-in` animation whose keyframes did not exist; stylesheet tests
  now require every referenced animation to be defined;
- full settings saves could race so an older async completion repainted over a newer local
  change; renderer state serialization is latest-request-wins and preserves dirty inputs;
- one ChatGPT response split across multiple assistant sections with no turn id could be rendered
  twice by overwrite; the first reconstructed section owns that response.

### 21. Reserved-root migration could create ambiguous virtual paths

**Where:** config/root migration + IPC tests

Legacy/migrated roots could collide with reserved virtual namespaces (notably `/skills`) or with
another root after name normalization. Migration and live rename now preserve unique safe virtual
root names, and a live rename into the reserved namespace is refused.

### 22. `session history` could spend its result budget on context and omit the actual match

**Where:** `src/main/mcp/tools-core.ts`, `test/mcp.test.ts`

Search history builds a small neighborhood around every hit. The old selector walked from
`match - 2` forward and stopped as soon as the presentation cap was full. With `limit: 1`, a real
hit at event 7 could therefore answer **"1 match" while returning event 5 and not event 7 at all**.

**Fix:** direct matches reserve the result budget first. Remaining rows are filled with nearest
context in rings and sorted back into chronological order. The focused regression failed on the
old code with `old-note-5` present and the matching `#7` absent.

### 23. The `session` MCP recovery contract had two schema lies

**Where:** `src/main/mcp/tools-core.ts`, `test/mcp.test.ts`

First, `session` exposes only `history` and `status`, both inspection operations, but advertised
`readOnlyHint: false`; MCP clients could consequently apply write/confirmation semantics to simply
reading the app's own recording. Second, a recorded call can legitimately spill roughly 16 MiB
across argument/result overflow assets, while the schema hard-stopped `history(call_id)` at part
200. A valid part 200 could literally instruct the model to request part 201 and the schema would
then reject part 201.

**Fix:** `session` is correctly marked read-only and the maximum part is derived from the actual
overflow-storage ceilings rather than a disconnected constant. Regressions cover both metadata
and a real page 201 recovery request.

### 24. A rejected Compact & Resume capture could already be published as the latest handoff

**Where:** `src/main/session/handoff.ts`, `src/main/session/continuation.ts`,
`src/main/session/recorder.ts`, `test/continuation.test.ts`

`createHandoff()` used to write the handoff file **and append the session `handoff` event** before
the continuation WAL transitioned from `awaiting-summary` to `awaiting-chat`. If that WAL write
failed, the continuation correctly stayed retryable but `meta.lastHandoffId` already exposed the
rejected brief to unrelated recovery callers. Retrying could then write a second handoff.

**Fix:** capture is now a two-store transaction with explicit ordering: prepare the handoff file,
durably publish the continuation state carrying its id, then publish the session handoff event.
Restart recovery repairs the opposite crash window, WAL committed but session event absent, by
idempotently ensuring that exact event once. Regressions exercise both boundaries.

### 25. Legacy append-only ChatGPT message revisions could crowd the real conversation out of Goal context

**Where:** `src/main/session/store.ts`, `src/main/goal.ts`, `test/session.test.ts`,
`test/goal.test.ts`

Canonical recordings replace stable messages in `messages.json`, but old recordings may contain
many append-only snapshots with the same ChatGPT message id. `readRecentEvents()` counted every
legacy revision against its row cap, so enough revisions of one long assistant answer could fill
Goal's entire recent window before it ever reached the user turn that answer belonged to.

**Fix:** newest-first recent scanning counts a stable legacy message identity once and continues
backward until it has the requested number of logical rows. Goal also defensively collapses
same-kind/same-message-id legacy rows, preserving first chronology with newest content while
leaving id-less rows distinct. The store regression failed pre-fix with two assistant revisions
and no user message.

### 26. A pre-UUID v4 swarm snapshot could restore the obsolete 32-bit incarnation fence

**Where:** `src/main/agents.ts`, `test/agents.test.ts`

Run identity moved from short random hex to a UUID without a snapshot-version bump. Restore still
trusted any v4 `runId`, so an upgrade could resurrect the weak old incarnation id and use it to
fence fresh durable worker commands.

**Fix:** a restored run id must satisfy the current UUID-v4 shape. Legacy v4 snapshots are re-keyed
to a fresh UUID while their agents, queues and unfinished bootstrap obligations are preserved.

### 27. A run could be released while a durability-gated message still existed

**Where:** `src/main/agents.ts`, `test/agents.test.ts`

Staged worker messages are deliberately hidden from ordinary `pending` counts until their
critical durability barrier succeeds. `releaseQuiescentRun()` checked that visible count but not
the unpublished queue. In a parallel finish/report ACK, visible work could reach zero and destroy
the run while a staged `agents action=message` was still waiting to commit; the sender could then
receive success for a message attached to an already-destroyed broker object.

**Fix:** unpublished queued messages count as outstanding work for quiescent release even though
they remain hidden from delivery/presentation counts.

### 28. Goal's ten-minute UI TTL could erase its lost-ACK idempotency key

**Where:** `src/main/goal.ts`, `test/goal.test.ts`

A Goal reply may already have crossed ChatGPT's irreversible send boundary while its local ACK is
lost. The old TTL deleted the whole draft after ten minutes. A later reload could therefore ask
for the same finished generation, receive a new token, bypass the browser's spent-token receipt
and send the same user message again.

**Fix:** expiry retires the visible/heavy payload but keeps the turn+token as an acknowledged
tombstone until a genuinely newer generation supersedes it.

### 29. Version-3 bridge command receipts were written but not restored

**Where:** `src/main/bridge.ts`, `test/bridge.test.ts`

The current bridge snapshot is version 3, including command completion receipts used to resolve
lost HTTP ACK responses. Restart recovery accepted receipts only from version 2. A command whose
semantic operation and receipt were both durable could therefore answer an exact post-restart
retry as "gone" rather than replaying its committed result.

**Fix:** receipt recovery accepts the current v3 shape as well as the compatible v2 shape. The
regression finalizes a command, loses the response, restores state and replays the exact ACK.

### 30. A dying ChatGPT document could reopen a terminal navigation lease while its replacement was loading

**Where:** `extension/background.js`, `test/extension.test.ts`

Direct navigation marks the old document terminal before the replacement registers. The old page
can still emit a delayed message during navigation. The recovery heuristic treated any mismatch
with the registered document as evidence that the terminal prediction was wrong, even while
Chrome reported `pendingUrl` for a new ChatGPT document. That let the dying A document reopen its
lease in the middle of A→B.

**Fix:** terminal prediction is overturned only after Chrome proves the original document is
settled again. A real in-progress navigation keeps the old document tombstoned; a genuinely
speculative/incorrect prediction can still recover once the tab is stable.

### 31. Goal could spend an OpenRouter request before the triggering transcript reached the app

**Where:** `extension/background.js`, `test/extension.test.ts`

Content-script acceptance means an observation is durable in the extension journal, not that the
app has recorded it yet. If `/events` was retrying when a finished answer triggered
`goal_draft`, the background worker called `/goal/draft` immediately. Goal then built context from
the older session and paid for a decision that did not include the answer it was reacting to.

**Fix:** Goal joins any in-flight journal drain and gives its conversation priority until the
worker can prove there are no accepted-but-undelivered rows for that conversation. If delivery
cannot be established it returns retryable `transcript_not_delivered` and does not call the Goal
route at all. The ordering regression observes `/events` before `/goal/draft` after recovery.

### 32. A worker's exact final report could be ACKed before the broker state carrying it was durable

**Where:** `src/main/bridge.ts`, `src/main/agents.ts`, `test/bridge.test.ts`

`/events` durably recorded a worker's final assistant message, called
`finishWorkerConversation()`, queued the exact worker→prime report, and then returned HTTP 200.
The terminal broker state/report still used the debounced swarm writer. A crash after that 200
let the extension retire its durable observation while restart restored the worker as active and
lost the exact result; the later orphan fallback could only manufacture generic completion text.

**Fix:** after auto-finish, `/events` crosses the critical swarm persistence barrier before it can
acknowledge the browser. Barrier failure is retryable HTTP 503, leaving the extension observation
available for idempotent replay. The new regression failed pre-fix with **HTTP 200 while the only
durable swarm snapshot still said `active`**.

### 33. An unused Goal cancellation route could cancel the wrong generation

**Where:** `src/main/goal.ts`, `src/main/bridge.ts`, `extension/background.js`, `test/goal.test.ts`

`/goal/ack` also accepted `cancel:true`, but that branch ignored the supplied draft token and
cancelled whichever draft currently occupied the conversation. A delayed cancel from generation A
could therefore retire generation B. Current content code did not use the branch, making it stale
protocol rather than a live caller worth preserving.

**Fix:** the unkeyed cancellation branch/API was deleted. Retirement has one protocol now:
conversation + exact draft token through `ackGoalDraft()`, which already aborts in-flight provider
work and keeps the generation tombstone.

### 34. Goal trusted provider-controlled HTTP/catalogue bodies beyond its UI needs

**Where:** `src/main/goal.ts`, `test/goal.test.ts`

Goal error handling used `response.text()` and model discovery used `response.json()`, so an
arbitrarily large OpenRouter body could be buffered before the app reduced it to a tiny status or
picker list. Catalogue cardinality and provider-controlled id/name fields were also uncapped
before caching.

**Fix:** provider responses use a streaming byte-bounded reader with both declared-length and
actual-byte enforcement: 64 KiB for diagnostic failures and 8 MiB for the catalogue. The cached
catalogue is capped at 5,000 models; ids over 500 characters are refused rather than truncated
into another identity and display names are capped at 500 characters. All three adversarial
provider-bound regressions pass.

### 35. Continuation tests were still exercising a dead, weaker transaction API

**Where:** `src/main/session/continuation.ts`, `test/continuation.test.ts`, `test/bridge.test.ts`,
`test/session.test.ts`

Production Compact & Resume uses the durable `openContinuationNow` / `armContinuationNow` /
`claimContinuationNow` path, but much of the continuation suite still built transactions with old
synchronous helpers whose mutations were merely debounced. That allowed the suite to stay green
without actually testing the WAL path production relies on. Separately, `session.test.ts` still
contained compile-only shims claiming to support a skipped 1.7 heuristic archive that no longer
existed anywhere in the file.
