# Bug Hunt 2026-08-25

Manual adversarial audit of Chat On Steroids / ChatGPT Local Files after the normal test suite was already green.

This pass deliberately focused on boundaries ordinary tests miss: crash windows, restart identity, browser/app lifecycle, long-lived UI polling, Windows process startup, virtualization/remount behavior, payload amplification, stale caches and unreachable UI paths.

## Status legend

- **FIXED** — regression added and implementation changed in this pass.
- **IN PROGRESS** — confirmed and currently assigned to an implementation worker.
- **CONFIRMED / DEFERRED** — reproduced or code-path-confirmed, but intentionally left for a separate change because the fix is broader or lower priority.
- **REJECTED** — investigated and not a real bug in the current implementation.

## Highest-risk correctness bugs

### 1. Crash recovery can accept stale session metadata over newer durable history — FIXED

`events.jsonl` and canonical message shards are durable before the debounced `meta.json` projection. A crash/reset in that window used to reopen a valid but older meta checkpoint without reconciling newer durable history. Counters, `activeTurnId`, `updatedAt`, `lastHandoffId` and related projection fields could remain permanently stale; a durable handoff could therefore become invisible to `latestHandoff()`.

The first recovery fix covered mutation/reopen paths through `ensureOpen()`, but a follow-up adversarial pass found a second boundary: `getSession()`, initial Chat/session-list catalog construction and other read-only paths still trusted stale `meta.json`. A user could restart after the crash window, open Chat history and see stale counters/handoff state indefinitely until some later mutation happened. Calling `ensureOpen()` from those reads would have been wrong too, because merely viewing old history would mark it live and exempt it from retention.

Fix: metadata carries durable history high-water state, and journal plus canonical-message high-water reconciliation now lives in a shared read-only durable snapshot path. It rebuilds/persists the projection only when disk proves the checkpoint stale, shares concurrent reconciliation, and does **not** insert historical reads into the live-session map. `ensureOpen()` reuses the same recovery primitive when a mutation really does make the session live. The process-lifetime attachment catalog is built from that authoritative read-only projection, so Chat listing and `latestHandoff()` recover before any new append.

Regressions: crash/reset before meta flush followed immediately by `getSession()` with no mutation; canonical message revision followed by read-only `listSessions()` after restart; the existing mutation-path and durable-handoff recovery cases remain. Focused recovery regressions passed.

### 2. Prime workspace could jump back to the pre-swarm project after a run ended — FIXED

Prime used `agent:prime` workspace identity while a swarm existed and `chat:<conversation>` after the run ended. Moving A → B during a run could therefore leave the old chat-key workspace at A, then the next post-run relative path silently resolved against A again.

Fix: explicitly reconcile prime workspace identity at the run boundary rather than inferring it from millisecond timestamps; stale prime-run identity no longer survives into a later run.

Regression: A → spawn → B → end → relative operation stays on B.

### 3. Actively refreshed request correlation could still be FIFO-evicted — FIXED

The request-owner registry is bounded, but same-owner re-observation updated `observedAt` without refreshing insertion/LRU order. After enough newer request ids, a still-live request could lose exact ownership despite the documented no-time-TTL invariant.

Fix: same-owner freshness now refreshes bounded-map order and persists the updated freshness; conflict ownership stays sticky.

Regression: fill the 50k registry, refresh the oldest live request, overflow by one, and prove the genuinely stale request is evicted instead. Correlation + continuation targeted suites passed 43/43.

### 4. Expired continuation could be revived with a fresh transfer lease after restart — FIXED

Normal waiting continuations expire after one TTL, but restore accepted snapshots up to two TTLs old and could call `beginPrimeTransfer()` for a nonterminal entry already past the ordinary lifetime. That reset the transfer timestamp and could pin a stale restored swarm for another full window.

Fix: restart recovery aborts nonterminal states already past the normal TTL before any prime-transfer reacquisition. Terminal committed records remain replayable in the longer recovery window.

Regression: expired waiting and pre-commit records cannot renew the transfer lease; terminal committed replay still works.

### 5. App-side “Disconnect browser” silently paired again on the next extension request — FIXED

App unpair used to clear only the server token. The extension still believed reconnect was allowed, received 401 on its next protected request, cleared its stale token and silently provisioned a new one.

Fix: explicit app-side disconnect is now a durable intent latch. Silent first-install/stale-token repair remains, while only an explicit browser Connect/Retry clears the disconnect latch. Bridge protocol was bumped for the new intent boundary.

Regression: app disconnect → extension activity/status cannot auto-pair; explicit reconnect succeeds. Bridge + extension tests passed.

## User-facing Overwrite / ChatGPT page presentation

### 6. Historical Overwrite fights ChatGPT virtualization while the user scrolls — FIXED

Live reproduction on 2026-08-25:

- With Overwrite **off**, historical scrolling is stable.
- With Overwrite **on**, scrolling can jump back up/down.
- As historical user/assistant turns enter the viewport, the page visibly updates; a user message can appear to disappear from view and the assistant/tool presentation can reshuffle.
- The desktop app transcript remains correctly ordered, isolating the fault to extension presentation rather than recording/storage.

Root shape: ChatGPT virtualizes/remounts historical `conversation-turn` sections during scroll. `renderStreams()` then hides the freshly mounted native assistant subtree and injects/rebuilds the app-owned reconstruction. This changes section height during the scroll and can also let a later Fiber snapshot select a different reconstruction candidate for the same mounted section.

Fix:

1. Wheel/touch/scroll-navigation input opens a short 240 ms presentation-only idle guard. During the gesture `renderStreams()` neither hides fresh native historical mounts nor rewrites an existing synthetic stream.
2. The first idle repaint captures a visible turn anchor and compensates the actual nested scroll container (window fallback) for the synchronous layout delta.
3. Recording/Fiber evidence is untouched and React-owned native DOM remains mounted.

Regressions: virtualized historical remount stays native during wheel input, an already-mounted synthetic stream is frozen through the gesture, and a nested transcript scroller preserves a visible user-turn Y position across the idle replacement. Full content-script suite passed 240/240 plus typecheck.

### 7. Persisted bridge token is not proof the extension is currently alive — FIXED

Setup and Chat settings treated `bridge.paired` as “Connected”, but pairing is durable while browser presence is process-local. Disabling/uninstalling the extension and restarting the app could therefore leave setup looking complete despite no browser being present.

Fix: `BridgeStatus` now separates durable `paired` authorization from live `present`. Presence is established only by authenticated compatible traffic in the current bridge lifetime, expires after browser silence, and is cleared on bridge restart. Setup requires `present` when browser-backed features are enabled; Chat settings says “Authorized, but … not currently connected” instead of lying.

Regression: a persisted token after app/bridge restart is paired but not present until the extension checks in again. Bridge + renderer/IPC/layout suites passed 154/154 plus typecheck in independent validation.

### 8. Browser setup remains required even when browser-dependent features are off — FIXED

If session recording and multi-agent are both disabled, Core coding tools can work without the extension, but the setup wizard still treated the browser step as unfinished.

Fix: one shared `browserExtensionRequired(config)` predicate defines the actual dependency (`sessions.record || multiAgent.enabled`). When false, the browser setup step is hidden/already satisfied and Chat settings explicitly says the extension is not needed right now. Goal alone is intentionally not counted because Goal cannot operate without recording; the invalid Goal+recording-off state is repaired separately in finding 34.

### 9. Recovery ZIP points to latest release, not installed app version — FIXED

An older installed desktop build could download the newest extension ZIP and manufacture a bridge protocol mismatch itself.

Fix: the renderer no longer supplies a moving GitHub URL. A dedicated main-process recovery action derives `releases/download/v<app.getVersion()>/Chat-On-Steroids-Extension.zip`; the normal bundled-extension path is unchanged.

Regression: mocked installed 1.8.8 opens the v1.8.8 artifact and never `/releases/latest/`. Recovery/IPC/extension suites passed 82/82 plus typecheck; worker build validation also passed.

## Setup and desktop window correctness

### 10. Fresh setup could skip the folder step merely because Desktop was enabled — FIXED

The previous gate treated “Desktop surface is useful” as equivalent to “this whole configuration is desktop-only”. Fresh defaults can enable Desktop alongside Core file/command capabilities, so the app could connect with zero roots and expose Core operations that had nowhere valid to run.

Fix: one shared `requiresApprovedFilesystemRoot()` rule now drives both main connection admission and renderer setup guidance. Screen/control/clipboard-only configurations remain legitimate rootless setups; file/search/patch/command capability sets require a root.

Regression: mixed Core + Desktop and command + Desktop are blocked rootless; screen-only and clipboard-only remain allowed. Targeted connection/renderer tests and typecheck passed.

### 11. Fixed non-resizable 1080×700 main window can exceed common Windows work areas under DPI scaling — FIXED

The BrowserWindow was fixed-size and non-resizable while the renderer also constrained page overflow. Small laptop work areas and 125–150% scaling could therefore make parts of the UI inaccessible.

Fix: initial outer bounds are capped and centered to Electron's current primary-display work area in DIPs, 1080×700 remains preferred, resize/maximize is enabled, minimums stay sensible without exceeding tiny displays, and Setup/Settings retain bounded vertical scrolling.

Regression: 900×520 and even 500×360 work areas cannot create a window larger than the usable display; renderer layout tests pin vertical reachability. Focused window/layout suites passed 29/29 plus typecheck.

## Session retention and Chat UI performance

### 12. Retention was startup-only and disabled when recording was off — FIXED

Expired recordings could remain indefinitely in a long-lived tray process, and turning recording off prevented startup cleanup entirely.

Fix: retention now runs immediately independent of `sessions.record`, then on a coarse six-hour singleflight maintenance interval using the current `retainDays`; shutdown owns the timer.

Regression: immediate prune, changed retention window on later sweep, no overlapping slow sweep. Retention + bridge/extension focused suites passed.

Follow-up found a completeness hole inside the store itself: `pruneSessions()` still consumed the legacy `readAllSummaries()` helper, which stops after 5,000 valid directory names **before** sorting. Since `readdir()` order is arbitrary, an expired session outside that prefix could survive every six-hour sweep forever.

Fix: retention now consumes the uncapped process-lifetime attachment catalog with live summaries overlaid. The same catalog is already maintained after durable create/rebind/delete operations, so later sweeps do not need another 5,000-folder scan and deletion updates the index immediately. Correctness-critical retention no longer uses the bounded compatibility/model-facing list.

Regression: a mocked 5,001-session store puts the only expired session at index 5,000; pruning removes that exact session while preserving the newest-handoff protection.

### 13. Live Chat refresh rereads session metadata and resends a large event tail on every small change — FIXED

The visible Chat tab could coalesce recorder updates to roughly once per second, yet each refresh historically called `listSessions()` and `getSession()` from scratch. `listSessions()` scanned/read metadata for many session folders, while detail reload cloned/sent hundreds of events and rebuilt the timeline for one new event.

Fix:

- a process-lifetime paged summary index pays metadata discovery once and overlays live sessions in memory;
- first detail load is bounded to the renderer's 160-row window, then live refresh uses a sequence cursor and bounded deltas;
- bursts larger than one page drain in 160-row chunks rather than lifting the payload cap;
- cursor reads page by sequence before applying presentation chronology, preventing reordered rows from being skipped at the page boundary.

Regression: hot refresh performs no repeated metadata scan, live/closed cache updates stay fresh, detail refresh switches to `{from,limit}` deltas, and burst paging remains bounded. Combined session/IPC/renderer/chronology suites passed 174/174 plus typecheck.

### 14. Chat UI hard-cap made old retained sessions inaccessible and called 60 “recorded sessions” — FIXED

IPC/renderer exposed only the newest 60 sessions without pagination/search while the store retained far more. The UI therefore mislabeled a page-size as the total and provided no route to older retained sessions.

Fix: `sessions:list` now exposes a bounded keyset page with `total` and `nextCursor`; scrolling the session list loads older pages and preserves them across live first-page refreshes. Footer copy reports e.g. `60 of 65 retained sessions shown · scroll for older history` rather than calling 60 the total.

Regression: 65 retained sessions page beyond the original 60-row boundary with an honest total and reachable older rows.

## MCP payload and tool latency

### 15. Windows explicit `yield_time_ms: 250` was silently clamped to ten seconds — FIXED

Still-running initial exec calls on Windows ignored the requested short yield and waited at least 10 s before returning a session id.

Fix: the 10 s **default** remains, but explicit 250–30000 ms values are now honored on Windows. Runtime parity regression passed.

### 16. Default Windows exec repeatedly resolved PowerShell and loaded the user profile — FIXED

Routine commands repeatedly walked PATH to rediscover the default shell, then defaulted to profile-loading PowerShell semantics. Slow/network profiles or PATH entries added latency and arbitrary startup output/aliases.

Fix: default shell resolution is cached against relevant environment inputs; Windows defaults to no-profile for deterministic/faster execution while explicit `login:true` remains available.

### 17. Dev-toolchain reachability still scans PATH before the memoized deep discovery — FIXED

`ensureDevToolchain()` checked PATH entries for Java/Go reachability for every command before consulting the cached deep discovery result.

Fix: Java/Go PATH reachability is memoized by probe + exact effective PATH with a small bounded cache, while explicit `JAVA_HOME` / `GOROOT` still win. Fresh child-environment objects therefore reuse the same filesystem verdict.

Regression: two fresh command environments with the same PATH cause filesystem probes only on the first call. Env suite passed 24/24 plus typecheck.

### 18. `view_image` serialized the same base64 image twice — FIXED

The native MCP image content already transports the bytes; structured `image_url` duplicated the same base64 and forced a lower raw image ceiling.

Fix: send only native image content, remove the redundant structured output and budget one base64 copy inside the wire envelope. `view_image` + MCP suites passed.

### 19. Clipboard reads were unbounded inside a 20-action desktop batch — FIXED

A huge clipboard could blow up one MCP result/context, multiplied by repeated `read_clipboard` actions.

Fix: clipboard presentation is capped per read and in aggregate with explicit truncation markers before becoming model output.

### 20. `observe what=windows` had no result cap — FIXED

A machine with many top-level windows could dump all of them into the model context.

Fix: window results now use the same bounded `max_elements` concept, default 60 / max 100, and tell the model when more matches exist.

### 20a. Ordinary MCP disconnect could force-close an accepted mutation before its result arrived — FIXED

The MCP endpoint used one shutdown policy for both final app exit and ordinary Disconnect/settings reconnect. `server.close()` began a graceful drain, but a fixed 30-second timer then called `closeAllConnections()`. A legal accepted request can exceed that boundary through caller-identity evidence plus a long `exec_command` yield. The caller could therefore receive a transport failure and retry while the original handler/child process was still running and able to commit, creating an ambiguous side-effect boundary.

Fix: endpoint stop is graceful by default with no force deadline. Ordinary user disconnects and settings-driven reconnects use that mode, so accepted requests keep their response socket until they settle. A separate final-app `shutdownConnection()` is the only lifecycle path that opts into the bounded 30-second force, immediately before process teardown.

Regressions: connection lifecycle proves ordinary `disconnect()` calls `endpoint.stop()` without force options while final shutdown supplies the explicit bound; MCP shutdown regression proves ordinary endpoint stop schedules no legacy 30-second force-close timer. MCP shutdown + MCP + connection suites passed 160/160 plus typecheck.

### 21. `exec_command` / `write_stdin` duplicate output in text plus structured output — CONFIRMED / DEFERRED

The same command output is represented twice on the MCP result path. Existing output ceilings bound each copy but serialization/context cost remains duplicated.

Compatibility review: this is not safely removable as a local micro-optimization. `output` is a required field of the advertised Codex-compatible output schema, while the text form is independently the normal model/display representation and carries human recovery notes. Dropping either changes the tool contract. Keep this as compatibility debt until the exec result schema is redesigned end-to-end with the target client.

## Tunnel/runtime discovery

### 22. PATH/common-dir `tunnel-client.exe` could silently override the packaged tested client — FIXED

Without an explicit path, discovery previously preferred PATH/common directories over the packaged binary. A stale external install could therefore receive newer CLI flags and fail even though the working tested client shipped with the app.

Fix: explicit user path still wins; otherwise the bundled tested binary wins and PATH/common dirs are fallback only.

### 23. Tunnel binary/version discovery performed repeated synchronous filesystem work on status pushes — FIXED

Renderer state rebuilds repeatedly resolved the binary and read the bundled version, potentially walking Windows PATH synchronously on a periodic main-process hot path.

Fix: locator/version results are cached against stable environment inputs. Regression verifies bundled preference and explicit override.

### 24. Development bundled tunnel path was off by one directory — FIXED

The dev fallback resolved `src/resources/tunnel` rather than repository `resources/tunnel`, so development silently skipped the bundled binary and fell through to PATH. The new bundled-preference regression exposed this immediately.

## Renderer races and UI semantics

### 25. API-key fields erased secrets when secure storage failed — FIXED

Both OpenAI and OpenRouter inputs cleared themselves after awaiting the storage call regardless of success. The user lost the key they needed to retry.

Fix: keep the submitted value on failure; clear only after successful storage.

### 26. Older async key save could erase a newer value typed while IPC was in flight — FIXED

Blur A → immediately type B → save A resolves used to clear the field containing B.

Fix: snapshot the submitted value and clear only if the field still contains that exact snapshot when success returns.

### 27. Whitespace OpenRouter key could remove the stored key while reporting “stored” — FIXED

Raw nonempty whitespace passed the initial check, trimmed to empty for IPC and invoked the remove-key path.

Fix: trimmed-empty input is ignored; explicit remove button remains the only remove path.

### 28. Rapid theme/read-only double-clicks can derive the second target from stale acknowledged state — FIXED

The second click could occur before the first save/state push updated the authoritative local snapshot, causing two clicks to behave like one.

Fix: both controls derive their next value from the latest requested settings snapshot, not only the last acknowledged app state. The existing serialized settings queue still owns IPC ordering and failure reconciliation.

Regression: hold the first save unresolved, double-click Read-only, change another setting, then double-click theme; queued snapshots preserve true→false and dark→light intent in order. Renderer state suite passed 14/14 plus typecheck.

## Bridge/session lifecycle leftovers

### 29. Bridge stop/start can leave an already-leased command without a re-armed deadline — FIXED

Stopping clears command timers but retains command/lease state. Restore skipped in-memory duplicates, so a surviving claimed command could return without its deadline and block later delivery.

Fix: bridge startup re-arms every retained in-memory lease from its existing `claimedAt`; already-expired leases are expired immediately instead of reopening the same bootstrap.

Regression: lease → bridge stop → clock passes deadline → bridge start produces no second browser open and fails/retires the expired worker command. Full bridge suite passed 91/91 plus typecheck.

### 30. Setup/browser status, extension ZIP version pinning and bridge lease restart — RESOLVED

These remained separate from the disconnect protocol change so user intent, liveness and credential repair were not conflated. They are now independently covered by findings 7, 8, 9 and 29.

## Lower-priority dead / unfinished paths

### 31. Root rename is implemented through IPC/preload but has no renderer caller — FIXED

The Home folder row now exposes the existing rename action with an inline editor, Enter/blur to save and Escape to cancel. The UI normalizes the name to the same lowercase namespace the backend validates.

A follow-up race showed the first renderer implementation violated its own “never rebuild a control the user might be typing into” rule: every unrelated state push rebuilt `#rootList` with `replaceChildren()`, destroying the transient rename input and its unsaved text. Bridge/tunnel status traffic was enough to trigger it.

Fix: rename target, path, draft, focus and caret live in renderer state rather than only in transient DOM. Folder repaints capture and recreate the editor across unrelated pushes, suppress repaint-induced blur commits, keep a failed rename draft available for retry, and cancel the editor if authoritative state actually removes/renames its target.

Regression: start renaming `/repo`, type `new-name`, preserve focus/value/caret across an unrelated state push, retry after a failed IPC rename, then prove authoritative root removal cancels the stale editor. Renderer-state suite passed 17/17.

### 32. `--connect-on-start` is documented as a self-update handoff but the repo has no updater/producer — FIXED CLEANUP

Repo-wide search found no updater (`autoUpdater`, `electron-updater`, `quitAndInstall`) and no producer/reference outside the flag itself. The stale one-shot startup override and its self-update comment were removed; startup connection again has one source of truth, the persisted `ui.autoConnect` preference.

### 33. File-local extension helpers with no normal callers — FIXED CLEANUP

Static sweep found seven named functions whose only textual occurrence was their declaration: `overBudget`, `terminalSender`, `isLiveSection`, `genericLabel`, `localBlockCount`, `localConnector`, and `thoughtOf`. Repo-wide exact-name search found no reflective/string invocation either, so they were removed. Extension + content-script suites passed 300/300 plus typecheck.

### 34. Goal Mode could be enabled while Recording was off even though Goal requires a recorded session — FIXED

`/goal/draft` reads the local session transcript and explicitly returns `session_not_recorded` without one, but configuration previously allowed `goal.enabled=true` together with `sessions.record=false`. That was a persisted setting which could never work.

Fix: the central config boundary now repairs this combination by turning Goal off while leaving Recording off. It deliberately never auto-enables recording behind the user's back. The invariant applies to renderer saves, extension writes and hand-edited/older config files. Config suite passed 32/32 plus typecheck.

### 35. Recorder takeover left extension-level listeners owned by the predecessor — FIXED

The recorder takeover cleanup removed MutationObservers and delegated DOM/window handlers, but the old isolated-world instance still kept its `chrome.runtime.onMessage` and `chrome.storage.onChanged` subscriptions. In a same-document reinjection, that predecessor could therefore answer the same health/revival message as its successor or repaint Overwrite after `alive=false`. The normal send path was already inert, but browser-facing ownership was not total.

Fix: runtime/storage listeners are named, unregistered through the same takeover cleanup stack, and additionally fail closed on `alive=false`. The content-script harness now models listener registration/removal and the takeover regression proves exactly one runtime and one storage listener remain after replacement. Targeted content-script suite passed 260/260.

### 36. `exec_command.cmds` could parse command-authored text as its own exit markers — FIXED

Batch execution used fixed human-readable `--- command N/M ---` / `--- exit code X ---` lines as both presentation and machine framing. Because command stdout is mixed into the same stream, a command that printed one of those lines could close its section early. A later benign search miss could then make the recorder classify a genuinely failed batch as benign even though the real wrapper exit was non-zero.

Fix: every composed batch now carries a fresh 96-bit framing id. The readable labels remain, but the parser accepts only command/exit markers carrying the exact id emitted before any command output. Ordinary command text can no longer collide with the framing accidentally. Regression pins the old early-close ordering; the focused batch parser and live MCP batch regressions pass.

### 37. One transient session-root scan failure could poison the process-lifetime attachment catalog — FIXED

The new uncapped attachment/retention catalog treated every `sessions` root `readdir()` failure as an empty directory and then cached that empty result for the rest of the process. A transient `EBUSY`, `EACCES` or I/O failure during the first authoritative lookup could therefore make conversation ownership, newest-handoff discovery and retention blind until app restart.

Fix: only `ENOENT` means a legitimate empty fresh-install store. Other root scan failures now propagate, the in-flight catalog build is discarded, and the next lookup retries from disk. Regression forces one `EBUSY`, proves the first safety-sensitive lookup fails closed, then proves the retry finds the durable conversation. Adjacent >5k attachment, newest-handoff and retention regressions remain green.

## Validation policy used in this pass

For correctness fixes the preferred sequence was:

1. Add a deterministic boundary regression that is red against the old implementation.
2. Fix the earliest state/identity/lifecycle root cause rather than patching the symptom.
3. Run the nearest suites.
4. Run TypeScript typecheck where the touched files participate.
5. Review the exact dirty diff because this repository is intentionally shared between workers and prime.

The repo was already heavily dirty from concurrent Computer Use / Goal work. No reset, checkout, clean, broad reformat or unrelated overwrite was used in this pass.

Final public-release validation after the later reusable-worker, completion, recorder-takeover, command-framing and session-catalog follow-ups: the privacy gate and typecheck passed; the exact committed test set passed 50/50 Vitest files with 1580 passed / 1 skipped; `npm run build` passed main/preload/renderer production bundles. A broader local run including intentionally uncommitted standalone regression files also passed. Diff hygiene was rechecked after the final edits, ignoring only Git's existing working-copy line-ending conversion warnings.
